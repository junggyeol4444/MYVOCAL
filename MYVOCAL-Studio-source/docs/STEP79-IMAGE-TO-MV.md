# MYVOCAL Studio — Step79 Image-to-MV

이 문서는 사용자 지정 **100단계 로드맵의 79단계**만 다룹니다. 기획안 66개 항목은 변경하지 않았고 Step78 누적 ZIP의 기존 소스를 확장했습니다.

## 목적과 사용 방법

등록된 **본인 또는 사용 허가받은 실제 사람의 사진**을 *텍스트 참고*가 아닌 **로컬 AI 이미지 변환 모델의 실제 이미지 입력**으로 사용하고, 해당 사진 기반 장면 정지 이미지를 이전 Step78의 SVD 엔진으로 짧은 동영상 클립으로 변환합니다.

1. `사람 / 캐릭터 등록`에서 프로필 유형을 **실제 사람(person)** 으로 선택합니다. 자료 사용 권한은 `내 모습/내 목소리(self)` 또는 출처·허가 범위가 작성된 `사용 허가(licensed)` 이어야 합니다. `Reference 분석용`은 생성에 사용할 수 없습니다.
2. 해당 사람 프로필에 PNG/JPEG 사진을 **대표 이미지 / 정면 / 측면 / 전신 / 표정 참고** 역할로 등록합니다. 원본 사진은 로컬 IndexedDB에 유지됩니다.
3. `뮤직비디오 만들기` 화면의 Step77에서 **ComfyUI 로컬 SD 이미지 체크포인트**를 확인·선택하고, Step78에서 **ComfyUI SVD/SVD-XT 영상 체크포인트**를 확인·선택합니다. 모델과 ComfyUI는 별도 설치해야 합니다.
4. `Step79 · Image-to-MV` 패널에서 실제 사람과 등록 사진을 선택합니다. 사진 변환 강도(0.2/0.35/0.5/0.65)를 선택합니다. 강도가 커지면 장면 변화는 커지지만 원래 얼굴을 유지하기 어려울 수 있습니다.
5. `선택 장면 사진→MV 클립 생성` 또는 `전체 해당 장면 순차 생성`을 누릅니다. 전체 제작은 **인물 미지정 장면과 선택한 사람으로 이미 지정된 장면**만 대상으로 합니다. **다른 캐릭터를 배치한 장면은 건드리지 않습니다.** 사용자 확인 없이 전체 자동 시작하지 않습니다.
6. 앱에서 실제 로컬 사진 파일을 읽어 세션 인증된 `/api/person-mv/generate`에 전송 → Windows 앱 로컬 브리지가 `127.0.0.1` ComfyUI `/upload/image`에 **실제 PNG/JPEG 바이트** 등록 → `LoadImage → ImageScale → VAEEncode → KSampler(denoise) → VAEDecode → SaveImage` 실행 → 결과 이미지 파일 저장 → 이전 Step78 `/api/video/generate` 호출하여 움직이는 WebP 클립 생성·별도 저장.
7. 완료된 각 장면은 프로젝트에 즉시 저장됩니다. 중간 오류 시 이미 저장된 원본 사진, 이전 이미지/영상, 음악/가사/목소리/캐릭터는 삭제하지 않습니다. 중단 버튼을 누르면 진행 중인 HTTP 요청을 취소하도록 요청합니다.
8. 프로젝트 전체 백업(`.myvocal.json`)은 선택 인물 원본 사진·장면 이미지·움직이는 클립과 `personMv` 메타데이터를 포함합니다. 복원 시 인물 ID·사진 Asset ID를 새 값으로 변경하며 기존 파일을 덮어쓰지 않습니다.

## 구현·보존 원칙

- 새로운 JavaScript 파일 `src/lib/imageToMv.js`(등록 사람·사진과 사용 권한 검증, 장면 연결·원격 호출), Go `desktop/person_mv.go`(사용자 컴퓨터 안의 ComfyUI 이미지 변환 브리지), `Video.jsx` Step79 패널.
- 장면 `personMv={personId,referenceAssetId,denoise}` 필드만 선택적으로 추가. Step77/78에서 사진 참조가 없던 프로젝트는 **기존 이미지 키 포맷 그대로** 유지합니다.
- `mvStoryboard` 사전 검사에 기존 Step77/78 생성 자산 필드 및 Step79 사진 연결 메타데이터를 허용하여, 실제 파일이 연결된 장면도 편집 가능한 수동 스토리보드 목록으로 검사합니다. 원본 이미지를 수동 스토리보드 JSON에 포함하지 않습니다.
- 이전 영상 이미지/클립은 새로운 Asset ID로 추가하므로 자동 삭제나 덮어쓰기를 하지 않습니다. 다른 인물로 전환한 프로젝트의 이전 클립은 생성 이력 표시가 달라질 수 있지만 원본 파일은 유지됩니다.
- 사용 권한은 **등록자가 선언한 정보 및 생성 요청 확인**에 따라 제한합니다. 이 기능은 얼굴 소유권을 생체인식으로 확인하거나 허가 계약을 법적으로 검증하지 않습니다.

## 중요한 제약과 미검증

- **실제 ComfyUI 모델 GPU 추론은 테스트 환경에 모델이 없어 검증하지 못했습니다.** 단위 테스트 및 모의 HTTP ComfyUI 서버를 사용했습니다. 로컬 모델은 호환성, 메모리 부족, 런타임 설정 등에 따라 실패할 수 있습니다.
- `img2img`는 원본 사진의 픽셀을 사용하지만, 일관된 얼굴 정체성/특징 보존을 보장하는 전용 얼굴 ID 제어 모델은 아닙니다. **사람의 얼굴이 매 장면 같다는 보장은 없습니다.** 정교한 얼굴 동기화/동일성 강화는 이후 관련 단계와 실제 모델 검증이 필요합니다.
- **Step79 결과 영상은 Step78과 같은 짧은 애니메이션 WebP 클립**입니다(14/25프레임, 6/8 FPS). 씬 길이로 맞추거나 음원 합성·Lip Sync·MP4 전체 출력하지 않습니다. 최종 MP4/전체 프로젝트 출력은 사용자 계획의 **98단계**, 실제 사람 Lip Sync는 **86단계**에 해당합니다.
- 다중 장면 생성은 모델 추론이 느리거나 저장 공간을 많이 사용할 수 있습니다. `.myvocal.json` 전체 백업 원본 파일 합계는 기존 **150MB 제한**이 있으므로 이미지와 영상이 많은 경우 백업 불가 오류가 발생할 수 있습니다. 이 제한을 제거했다고 주장하지 않습니다.
- 모의 서버 성공은 실제 Windows PC에서 마우스로 UI를 클릭하고 모델을 설치해 영상까지 생성했다는 뜻이 아닙니다. **Windows 10/11 실기기 실행/모델 추론/시각적 품질 검증 미완료.**
- ComfyUI는 로컬 `127.0.0.1:<사용자 선택 포트>`만 사용하며 외부 API, 클라우드, 모델 자동 다운로드를 추가하지 않습니다.

## 이번 단계와 다른 단계 구분

- 77단계: 장면 텍스트→기본 로컬 이미지 생성 (기존 기능 유지).
- 78단계: 생성 정지 이미지→짧은 SVD 영상 클립 (기존 기능 유지).
- **79단계: 허가된 실제 사람 등록 사진→img2img 장면→SVD 클립 연결 (이번 추가).**
- **80단계: 사용자가 등록한 일러스트·캐릭터로 Character-to-MV PV 제작 (미진행).**
- 81~100단계: 캐릭터 애니메이션/Lip Sync/최종 합성 등 미진행.
