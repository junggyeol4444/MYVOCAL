# Step62 · Character Studio · 수동 룩 프리셋 및 외형 기준 재검토

## 새 기능

- Step61 캐릭터의 ID·기존 첨부 파일을 그대로 재사용해 **의상, 표정, 포즈/동작, 배경, 장신구 변경, 연출 메모**를 개별 룩으로 등록.
- 캐릭터별 최대 24개 룩을 이름과 ID로 구분. 동일 이름(대소문자 무관), 중복 ID 및 잘못된 참고 자료 ID 거부.
- 캐릭터에 등록된 **이미지·3D 모델**만 룩 참고 자료로 선택. 동작 영상은 별도 역할로 유지하며 룩 대표 자료로 사용하지 않음.
- 신규 룩 등록 시 기준 외형 4개 값(머리·눈·체형·대표 색상)을 **문자열 스냅샷**으로 기록. 캐릭터의 기본 외형을 수정하면 일치 여부를 계산해 **재검토 필요** 표시.
- 재검토 후 사용자 확인을 받아 현재 외형 기준으로 룩을 다시 승인. 실제 얼굴 이미지 비교나 Identity Lock AI는 아님.
- 룩만 선택적으로 제거할 수 있음. 파일·캐릭터·프로젝트는 삭제하지 않음.
- '룩 JSON 저장'은 캐릭터 외형 메타데이터, 룩 정의와 재검토 개수만 내보냄. 원본 이미지·영상·3D 파일의 바이트는 포함되지 않음.

## 단계 연속성

- Step61의 `normalizeCharacterIdentity` 편집 경로는 기존 객체의 추가 필드(`looks` 포함)를 계속 보존합니다.
- 로컬 저장소 키, IndexedDB 파일 키, 프로젝트 연결 ID를 마이그레이션하거나 초기화하지 않습니다.
- 기존 캐릭터의 `looks` 필드가 없어도 새 프리셋을 등록할 수 있습니다.
- 승인/삭제로 인해 원본 첨부 파일을 삭제하지 않습니다.

## 제한 및 안전

- **수동 메타데이터 비교**이며 얼굴 인식, 옷 합성, 렌더링, 장면 자동 생성, AI 연출 기능이 아닙니다.
- 사용 허가 확인은 기존 캐릭터 등록의 사용자 기재 내용을 따릅니다. 권한을 법적으로 검증하지는 않습니다.
- JSON에는 자료 식별자와 설정 텍스트만 있으므로 다른 컴퓨터에 JSON만 옮겨서는 원본 파일이 복원되지 않습니다.
- 기존에 연결한 파일이 사라지면 재검토 경고를 유지합니다. 새 외형을 재승인해도 원본 파일 누락 경고는 남습니다.
- Windows x64 교차 빌드는 실행 파일 생성 사실만 확인하며 실제 Windows 실기기 실행은 별도 검증이 필요합니다.
