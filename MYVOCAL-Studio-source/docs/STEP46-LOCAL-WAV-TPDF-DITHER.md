# Step46 — 오프라인 WAV 16비트 TPDF 디더

- 원본 MYVOCAL 66개 기획 중 믹싱·마스터링 관련 작업의 제한적인 추가 기능. 별도의 100단계 계획은 만들지 않음.
- WAV 내보내기 화면의 **「16비트 TPDF 디더」** 체크박스는 기본적으로 꺼져 있음. **16비트 PCM**일 때만 활성화. 24비트 WAV에는 디더를 적용하지 않으며 API에서 잘못된 조합은 명시적으로 거부.
- 16비트 정수 양자화 직전, **독립 균등분포 두 개의 차이와 동등한 삼각분포 노이즈**를 +/-1 LSB 이내에서 가산. 선택한 채널(모노/스테레오), 앞뒤 무음 제거, 경계 페이드, 피크 보호 또는 정규화 gain을 적용한 **최종 출력 샘플**에만 적용.
- 난수는 로컬 고정 시드 xorshift32를 사용해 **같은 입력·옵션이면 WAV 바이트가 동일**하게 재현됨. 암호학적 난수나 네트워크 호출 없음. 채널별 독립 시퀀스를 따로 만들지 않고 인터리브 순서대로 2회 균등 난수를 소비함.
- 디더를 끄면 이전 버전 16/24비트 PCM 바이트 경로를 그대로 사용. 24비트 기본 출력도 동일. 오디오 원본, 프로젝트 데이터, 미디어, 브라우저/WebView2 프로필을 변경하지 않음.
- **주의:** 디더를 켜면 무음 구간에도 매우 작은 잡음(최대 1 LSB)이 생김. 원본 신호 해상도를 올리는 기능이 아니며, 노이즈 셰이핑·트루 피크 리미팅·LUFS 정규화가 아님. 디더는 양자화 직전이므로 정규화 피크 분석과 달리 PCM의 마지막 ±1 LSB는 분석 대상이 아님. 매우 작은 신호를 16비트로 줄일 때만 유용하며 필요하지 않으면 끄는 것이 좋음.
- 단위 테스트: `node --test tests/wav-dither.test.mjs`; 모의 오프라인 믹스 API 통합 테스트: `node --test tests/wav-dither-integration.test.mjs`; 전체 회귀: `npm test`.
- 합성 오디오 비교 샘플: `node scripts/demo-wav-dither-step46.mjs <출력폴더>`.
- Windows 10/11 실기기·실제 WebView2·청감 검증은 별도로 필요.
