# Step76 — MV 연출 모드 (기존 Step75 위에 누적)

## 원래 개발 로드맵의 작업
76. MV 연출 모드 — Performance MV, Story MV, Mixed MV와 캐릭터 등장 강도를 선택한다.

이 단계는 기존 Step71~75의 **수동 스토리보드 → 애니매틱 → 컷 시트/컷북** 구조에 실제로 연결되는 **연출 계획 메타데이터** 기능이다. Step77 이미지 생성, Step78 AI 영상 생성, Step85 Lip Sync 등의 기능을 앞당겨 추가하거나 완성으로 표시하지 않는다.

## 사용법
1. 프로그램 실행 → 프로젝트 선택 → `Music Video Studio`로 이동한다.
2. `Step76 · MV 연출 모드`에서 `Performance MV`, `Story MV`, `Mixed MV` 중 하나를 선택한다. 과거 프로젝트의 `Vocal Synth PV`도 그대로 유지된다.
3. `캐릭터 등장 강도`에서 `캐릭터 중심`, `캐릭터 + 배경 반반`, `스토리 중심`, `캐릭터 가끔 등장`, `AI가 결정` 중 하나를 선택한다.
4. 공연·스토리 장면 시간과 인물 등장 **목표** 비율을 확인한다. 장면 선택 시 `Step76 · 선택 장면 연출`에서 개별 역할을 사용자 지정하거나 `자동`으로 되돌릴 수 있다.
5. `연출 큐시트 JSON 저장 · Step76` 버튼으로 읽기 전용 연출 계획을 내려받는다. 이 파일은 기존 Step71 스토리보드 JSON 복원과 **다른 형식**이며 프로젝트나 미디어 파일 자체가 아니다.
6. Step73 애니매틱은 장면이 진행되는 동안 해당 장면의 연출 역할과 목표 등장 비율을 글자로 보여준다.

## 정확한 구현 범위
- Performance: 모든 장면을 공연 중심으로 계획한다.
- Story: 모든 장면을 서사 중심으로 계획한다.
- Mixed: 장면을 **시간 순서대로** 스토리·공연·스토리·공연 순으로 나누어 계획한다. 이 로컬 규칙은 AI 분석을 의미하지 않는다. 한 장면만 있거나 수동 오버라이드 때문에 한 유형으로만 구성되면 경고가 뜬다.
- 등장 강도: 캐릭터 중심 90%, 반반 50%, 스토리 중심 25%, 가끔 등장 10%의 **계획상 시간 목표**. `AI가 결정`은 아직 실제 AI 엔진이 없으므로 공연 장면 80%, 스토리 장면 35%의 로컬 규칙이다.
- 장면 역할은 `project.mvDirectionOverrides`에 선택적으로 기록한다. 기존 프로젝트에서는 이 필드가 없으므로 새 마이그레이션이나 기존 미디어 수정이 필요 없다.
- `mvMode`와 `presence`는 기존 프로젝트 필드를 그대로 사용한다. 수정된 필드만 저장되어 기존 오디오, MIDI, 캐릭터, 사진, 영상, 트랙, 음성 모델 데이터는 변경하지 않는다.
- Step71의 스토리보드 장면 스키마와 Step72의 JSON 가져오기 버전은 **변경하지 않는다**. 기존 애니매틱, 컷 시트/컷북 출력 방식도 그대로 유지한다.
- 연출 계획의 캐릭터 연결 여부가 경고로 표시된다. 등록된 캐릭터가 없더라도 계획 비율은 *목표*로만 표기한다. 인물 배치가 실시간으로 이뤄진다고 주장하지 않는다.
- 오프라인, 외부 서비스/API 호출 없음. 캐릭터 이미지, 원본 음악, 영상 파일, 녹음, 가사 및 프로젝트 전체 데이터를 연출 JSON에 넣지 않는다.

## 검증/주의
- Step76 신규 자동 테스트 47개, 기존 1,468개를 포함한 전체 JS 테스트 1,515개 통과.
- Windows 호스트 Go unit/race/vet, Python 로컬 어댑터, Windows x64 크로스 빌드 시행.
- Windows 10/11 실기기 GUI 실행, 사용자 실제 프로젝트의 저장/재시작 및 음영상 확인은 아직 **미검증**.
- **출력은 영상이 아니며 AI 이미지/영상 렌더링, 실제 화면 등장 비율 계측, 자동 춤·Lip Sync 기능을 제공하지 않는다.**
