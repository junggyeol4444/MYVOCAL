# Step36 — 오디오 클립 비파괴 복제

## 기능
- 음악 작업 공간 → 오디오·MIDI 멀티트랙 편집기 → 오디오 클립 목록에서 **뒤에 복제** 또는 **커서에 복제**를 선택합니다.
- **뒤에 복제**는 현재 클립의 **실제 재생 종료 위치**에 새 클립을 놓습니다. 원본 전체 길이가 아니라, 원본 앞부분 건너뛰기·재생 길이 편집 결과를 기준으로 계산합니다.
- **커서에 복제**는 재생 위치 슬라이더 또는 마디 눈금에서 지정한 현재 위치에 복제합니다. 0초 및 소수 마디를 지원합니다.
- 새 클립은 별도 ID를 가지며 같은 로컬 `assetId`를 참조합니다. 파일 자체를 복제·수정·삭제하지 않습니다.
- 비파괴 자르기, 페이드 길이·곡선, 음량·음소거, 좌우 위치를 모두 복제합니다. 원본 클립의 설정을 이후 변경해도 복제본의 메타데이터는 별도로 관리됩니다.
- 원본 및 다른 트랙을 수정하지 않고, 원본 클립 바로 다음에 복제본을 삽입합니다. 위치가 겹치면 두 클립이 함께 믹싱됩니다.
- 999마디를 넘는 위치, 유효하지 않은 클립/커서/BPM은 거부합니다.

## 기존 데이터 보존
- 프로젝트 저장소, IndexedDB 미디어 저장소, WebView2/브라우저 프로필 관련 코드는 변경하지 않습니다.
- 기존 프로젝트 JSON 포맷은 변경하지 않습니다. 복제본은 기존 클립 필드와 새 ID/시작 마디만 사용합니다.
- 파일을 공유하므로 복제본을 제거하더라도 원본 파일은 삭제되지 않습니다. **프로젝트 JSON만 별도 저장하면 미디어는 포함되지 않으므로 전체 백업 기능을 사용하세요.**
- 재생 중 클립을 복제하면 기존 안전 정책에 따라 재생을 중지합니다. 다시 재생하면 복제본이 포함됩니다.

## 검증 범위
- 순수 함수 단위 테스트 12개: 클립 종료 위치 계산, 소수 마디 커서, 레거시 호환, 설정 보존, 불변성, 트랙 보존, 입력 오류, UI 연결.
- 기존 전체 JavaScript·Go·Python 회귀 테스트와 오프라인 HTML/Windows x64 교차 빌드를 별도로 실행합니다.
- Windows 10/11 실제 GUI/WebView2/스피커 실행은 이 Linux 개발 환경에서 검증할 수 없습니다.
- GitHub·외부 서버·클라우드 AI API는 사용하지 않습니다.
