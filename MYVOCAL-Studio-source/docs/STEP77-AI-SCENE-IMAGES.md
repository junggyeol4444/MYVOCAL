# MYVOCAL Studio — Step77: AI 장면 이미지 생성 (로컬 ComfyUI)

## 원래 계획의 77단계만 구현

원문: **77. AI 장면 이미지 생성 — 스토리보드에 따라 배경과 캐릭터가 등장하는 장면 이미지를 만든다.**

76단계의 Performance/Story/Mixed MV 연출 계획과 71~75단계의 스토리보드·애니매틱·컷 시트·컷북을 변경하거나 제거하지 않는다. **78단계 영상 생성/79단계 Image-to-MV/80단계 Character-to-MV는 구현했다고 주장하지 않는다.**

## 실제 동작 구조

1. 사용자 PC에서 직접 실행되는 `ComfyUI`와 호환 이미지 체크포인트(표준 `CheckpointLoaderSimple`/`KSampler`/`VAEDecode`/`SaveImage` 노드)를 사용한다. ComfyUI와 신경망 가중치는 이 ZIP에 포함되지 않는다.
2. Windows EXE에서 프로젝트의 `Video Studio`를 열어 `Step77 · AI 장면 이미지 생성` 패널에서 로컬 포트(기본 8188)로 연결을 검사한다. 실제 연결된 체크포인트 목록을 조회한다.
3. 장면 설명·장소·캐릭터 등록 이름/외형 텍스트·의상·표정·행동·카메라·조명과 **Step76의 연출 역할**을 편집 가능한 생성 프롬프트로 조합한다. 캐릭터의 첨부 이미지/3D 모델을 모델에 주입하는 이미지 조건화는 아직 없다. `reference`만 허가된 캐릭터는 새 이미지 생성에 사용하지 않는다.
4. 체크포인트, 이미지 크기(512×512, 768×448, 1024×576), 스텝, 시드를 선택해 이미지 생성한다. 실제 로컬 ComfyUI가 `POST /prompt` 작업을 수행하고 `GET /history/{id}`에서 완료 결과를 찾고 `GET /view`에서 이미지 바이트를 받는다. 생성기는 220초의 요청 제한 내에서 완료해야 한다.
5. 이미지 파일은 기존 브라우저/앱의 **IndexedDB**(`myvocal-assets-v01`)에 고유 Asset ID로 저장한다. 프로젝트 JSON에는 해당 장면의 `imageAssetId`와 생성 메타데이터만 선택적으로 추가한다. 이미지는 미리보기·애니매틱·스토리보드 장면 목록에서 확인하고 PNG/JPEG로 개별 저장 가능하다.
6. `프로젝트 전체 백업 .myvocal.json`의 미디어 목록에 장면 이미지도 포함시킨다. 복원 시 새 이미지 Asset ID로 안전하게 매핑한다. 기존 Step71 **장면 계획 JSON**은 미디어가 포함되지 않으므로 실제 이미지 백업에는 **전체 프로젝트 백업**을 사용해야 한다.

## 설정 및 사용 순서

- 설치/준비: 자신의 Windows PC에서 ComfyUI를 로컬(예: `127.0.0.1:8188`)에서 실행하고, 사용 권한이 있는 SD 계열 체크포인트를 `models/checkpoints`에 배치한다. ComfyUI/모델 설치는 사용자 장비 상황에 따라 별도로 필요하다. 인터넷 서비스나 외부 계정은 요구하지 않는다.
- MYVOCAL **EXE** 실행 → 프로젝트 열기 → Music Video Studio → 장면 편집/캐릭터 지정 → Step77 패널의 `로컬 AI 엔진 연결 확인` → 체크포인트 선택 → `현재 장면 AI 이미지 생성`.
- 이미지 생성 성공 후 장면에 저장된 이미지를 확인하고 전체 프로젝트 백업을 만든다. 장면/인물/연출 설정을 바꾸면 기존 이미지는 삭제되지 않고 **재생성 필요** 메시지가 나타난다. 다른 장면은 선택하여 개별 생성한다.
- **독립 실행 HTML**(EXE 없이 HTML만 연 파일)은 보안이 적용된 Go 로컬 브리지가 없어 AI 생성이 불가하다. 수동 장면 편집과 저장은 기존대로 이용한다.

## 호환성·데이터 보호

- 기존 프로젝트·트랙·녹음·목소리·캐릭터 파일, 저장 포트 `127.0.0.1:58319`, 기존 WebView/브라우저 프로필 및 LocalStorage 저장 키는 바꾸지 않는다.
- 이미지 저장은 **완료된 이미지 검증 이후**에만 프로젝트의 장면 링크를 변경한다. 생성 실패·시간 초과·장면 변경 중 충돌 발생 시 기존 연결 이미지는 그대로 둔다. 구 이미지 파일은 안전하게 보존하며 자동 삭제하지 않는다.
- Windows 앱의 브리지는 랜덤 세션 키 + 같은 Origin 검사, 요청 크기 제한, localhost 단독 주소, 다른 서버로 리다이렉트 금지, 환경설정 프록시 미사용 및 타입/이미지 크기 검사를 적용한다.
- ComfyUI는 자체 출력 폴더에도 파일을 저장한다. 외부 서비스로 프로젝트·사진·프롬프트를 전송하지 않는다.
- **실제 Identity Lock, 참조 이미지 조건화, 영상 프레임/모션, Lip Sync, Dance 등은 이 단계 구현 범위가 아니다.**

## 검증 경계

- 2026-10-14 환경: Go 모의 로컬 ComfyUI HTTP 서버로 체크포인트 조회 → 생성 요청 → 대기/수신 → 이미지 바이트 검증의 끝단까지 테스트했음.
- PNG 백업 복원 Asset ID 재매핑과 기존 JS 회귀 테스트 실행함.
- 이 개발 환경에서 **실제 ComfyUI GPU/체크포인트 inference, 생성 화질, Windows 10/11 PC 앱 실행은 검증하지 못함**. EXE 성공적인 교차 빌드를 실제 Windows 검증으로 표시하지 않는다.
