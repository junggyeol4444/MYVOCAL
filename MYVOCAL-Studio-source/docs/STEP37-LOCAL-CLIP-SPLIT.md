# Step37 — 재생 커서에서 오디오 클립 비파괴 분할

## 사용 방법

1. 음악 작업 공간의 **오디오·MIDI 멀티트랙 편집기**에서 재생 위치 슬라이더나 마디 눈금을 클릭해 커서를 이동합니다.
2. 하단 오디오 클립 목록에서 분할할 파일의 **커서에서 분할** 버튼을 누릅니다.
3. 커서가 클립의 **실제 재생 구간 내부**에 있고 양쪽에 최소 0.01초가 남아 있으면, 클립이 두 개로 나뉩니다.
4. 두 조각은 각각 위치·원본 시작 초·재생 길이를 별도로 수정할 수 있습니다. 분할한 뒤 원본으로 돌아가려면 전체 백업에서 복원하거나 두 조각을 직접 편집해야 합니다. **자동 실행 취소/병합은 이번 단계에서 제공하지 않습니다.**

## 원본 파일과 기존 프로젝트 보존

- 분할은 프로젝트 클립 메타데이터만 변경하며 원본 오디오 파일을 복사·자르기·삭제하지 않습니다. 두 조각은 동일한 로컬 IndexedDB `assetId`를 공유합니다.
- 왼쪽 조각은 기존 클립 ID를 유지하고, 오른쪽 조각은 새 클립 ID를 받습니다. 나머지 트랙·클립·MIDI·비디오·음성 자료는 수정하지 않습니다.
- 소수 마디를 이용해 커서의 초 위치를 그대로 유지합니다. 이후 프로젝트 BPM을 변경하면 기존 바 기반 클립과 마찬가지로 초 위치가 변할 수 있습니다.
- 분할 이전의 페이드 인/아웃 시간과 곡선은 선택적 `fadeReference` 메타데이터로 원래 클립의 **시간 기준**을 유지합니다. 실시간 재생과 WAV 내보내기는 동일한 페이드 함수와 스케줄러를 사용합니다.
- 분할 조각의 페이드 길이·곡선 또는 원본 자르기 설정을 직접 변경하면 해당 조각의 `fadeReference`만 제거하고 그 조각의 현재 설정을 기준으로 다시 페이드합니다. 시작 마디 이동, 클립 음량·음소거·좌우 배치 및 복제는 참조 페이드를 유지합니다.
- 기존 프로젝트에는 `fadeReference` 필드가 없어도 됩니다. 저장 형식 버전이나 저장소 스키마를 변경하지 않습니다.
- 프로젝트 JSON만 별도로 저장하면 실제 WAV 미디어는 포함되지 않습니다. 기존 전체 백업 기능을 사용하세요.

## 검증 범위와 제한

- 순수 함수 단위 테스트: 클립 시간/원본 오프셋 연속성, 페이드 곡선 연속성, 재분할, 불변성, JSON 저장/복원, 잘못된 커서/BPM/ID 및 다른 트랙 보존.
- Web Audio/IndexedDB 모의 객체를 사용한 통합 테스트: `AudioEngine.play()`의 분할 재생·시크, `mixdownWav()`의 선형/비선형 페이드 출력 PCM 비교.
- 비선형 페이드는 기존 32개 선형 보간 구간을 사용하는 근사 처리입니다. 분할 경계에서 재보간하므로 실시간 재생과 WAV의 샘플이 미세하게 달라질 수 있으며, 실제 스피커에서의 클릭/무음 여부는 검증하지 않았습니다.
- Windows 10/11 실기기 GUI·WebView2·실제 오디오 출력 테스트는 아직 진행하지 못했습니다. 이 기능은 AI 목소리 학습이나 영상 생성이 아닙니다.
- GitHub·원격 저장소·외부 서버·클라우드 AI API는 사용하지 않습니다.
